# Infrastructure for Küü on Google Cloud

Two ways to build the same foundation (migration plan Steps 1 to 4). **Pick one per project**; do not mix them.

| | [terraform/](terraform/) | [setup-gcp.sh](setup-gcp.sh) |
| --- | --- | --- |
| Good for | Repeatable, reviewable, easy to change later | One-off setup with only `gcloud` installed |
| Re-running | `terraform apply` shows and fixes drift | Re-run is safe but only creates what is missing |
| Secrets | Generated by Terraform, so they sit in its **state** (use a private GCS backend) | Generated in the script and written straight to Secret Manager |
| Not covered | The GCS state bucket, project creation | Domain mapping is a printed command; no drift detection |

Both create: the project's APIs, the `kuu-run` and `kuu-deploy` service accounts, Artifact Registry (with cleanup), Cloud SQL PostgreSQL 17 (backups and point-in-time recovery, no authorised networks), the uploads bucket (private, versioned), the `kuu-db-url` and `kuu-secret-key` secrets, Workload Identity Federation limited to this repository's `main` and `v*` tags, the Cloud Run service (instance-based CPU, min 1, concurrency 1000) and budget alerts. Terraform also creates the domain mapping.

Both start the service on Google's sample image. The first CI deploy replaces it with the real image and keeps every setting.

## Terraform

```bash
cd deploy/terraform
cp terraform.tfvars.example terraform.tfvars   # edit it; it is git-ignored
gcloud auth application-default login
terraform init && terraform plan && terraform apply
terraform output github_variables               # paste into GitHub repository variables
terraform output dns_records                    # add in Cloudflare, DNS-only (grey cloud)
```

The project must already exist with billing linked. Set `create_domain_mapping = false` until the domain is verified, then apply again. Add `ANTHROPIC_API_KEY` or SMTP as secrets by creating them in Secret Manager and listing them in `secret_env`; do not add them with `gcloud run services update`, because the next `terraform apply` would remove them.

## Script

```bash
PROJECT_ID=kuu-prod REGION=europe-west1 DOMAIN=app.example.com \
BILLING_ACCOUNT=000000-000000-000000 OPERATOR_EMAILS=you@example.com \
CREATE_PROJECT=1 ./deploy/setup-gcp.sh
```

## Before launch

Set registration to `open` (`registration` in Terraform, `SOFTEX_REGISTRATION` otherwise) and redeploy. Keep a copy of `kuu-secret-key` outside GCP.
